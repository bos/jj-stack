jj-stack 0.1.7 handles partial stack merges much more reliably, and `view` and `list` show which PRs are ready to merge.

## Highlights

- `view` prints a lot more useful information: it marks each PR with ✓ or ✗ for whether GitHub would merge it now, shows approvals, and says how far the stack is behind its base.
- `list` displays a one-line summary per stack, such as `1 of 2 ready, 82 behind main`.
- Unresolved threads and missing required checks show up for every PR in a GitHub stack, not just the bottom one.
- `sync` no longer gets stuck when GitHub rewrites the rest of a stack after a partial merge or **Rebase stack**, unless someone else pushed to a PR branch.
- `merge` waits for GitHub to finish updating the remaining PRs instead of asking you to run `sync`.
- jj-stack respects jj's `git.sign-on-push`.
- `submit` uses GitHub's default PR template when the repo has no local one.

## Fixes

- `sync` and `merge` no longer leave uncommitted working-copy edits behind on the old base.
- With multiple workspaces, `sync` no longer refuses to clean up a merged change checked out in the current one.
- The recovery hint for a merged change you edited afterwards has been corrected to give accurate guidance.
- If a PR's changes reach trunk some other way and GitHub closes it as empty, `sync` tells you how to get unstuck.
- `merge` no longer crashes if another `sync` finishes the job while it waits.
- Abandoning or squashing the top change of a stack no longer loses the stack overview comment.
- PR titles and bodies resume following your change descriptions after an interrupted `submit` or a `relink`.
- jj config settings `ui.color = "always"` and `ui.quiet = true` no longer break jj-stack.
- `view` warns when PR branches were fetched into jj, which makes your commits immutable, and suggests `jj-stack doctor --fix`.

## Automation

- Removed `merge_details_error` from JSON output.
- `merge --output=jsonl` emits a `merge_requested` record when GitHub accepts the merge.
- Exit code 12 means another jj-stack command is busy with the repo; retry later.
- `view` and `list` accept `--ignore-working-copy`.
